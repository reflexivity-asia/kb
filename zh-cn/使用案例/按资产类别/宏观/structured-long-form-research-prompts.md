# 用长指令结构化复杂研究

## 什么时候适合这种方法

对于范围很大的研究主题，如果只写一句“分析这个主题”，研究范围、比较框架和最终要得到什么结论都可能不清楚。

原资料展示了另一种方式：把**要比较什么、按什么顺序调查、最后希望以什么决策格式输出**直接写进研究指令。

长 prompt 的目的不是字数多，而是拆解。复杂研究任务在明确以下四项后更容易控制：

1. 目标行业或实体；
2. 一套共同评价维度；
3. 地理或价值链敞口等二阶影响；
4. 最终综合格式，例如矩阵或优先级清单。

## 示例 1：比较不同行业的脱碳需求

原 prompt 要求对发电、石油与天然气、钢铁、水泥、化工、交通、农业和建筑进行全球比较，并规定统一研究顺序：

- Scope 1/2/3 绝对排放量和排放强度；
- 技术减排路径及成熟度；
- 可获得时的边际减排成本曲线；
- 地区政策风险；
- 对供应商、客户和替代风险的二阶影响；
- 最终用优先矩阵区分最大排放行业与最难减排行业。

关键设计是以下推进顺序：

**排放规模 → 减排技术 → 减排成本 → 政策差异 → 价值链 → 优先级排序。**

这样直到最终综合前，都不会把“排放最大”和“最难脱碳”混成同一个问题。

原资料链接到一个私有 Research 结果。本公开页面不重构无法访问的输出。

## 示例 2：从事件扩展到受影响企业

原资料还给出大型企业事件的 prompt 模式，例如计划中的大型美国 IPO。

研究指令可以明确按以下步骤推进：

**事件 → 直接受益 / 负面影响企业 → 历史类似案例 → 更广泛市场影响。**

这比只问“哪些公司和事件有关”更有用，因为它定义了如何把事件转化成研究地图。

## 示例 3：用历史事件寻找当前潜在受益者

另一个 prompt 要求以前五届足球世界杯为证据，寻找可能从世界杯受益的美国和日本企业或行业。

顺序有意设计为：

**历史案例 → 反复出现的受益模式 → 应用到当前美国和日本市场。**

这样可以减少在没有历史验证的情况下，直接从当前事件想象受益公司的风险。

## 示例 4：把政治事件拆成多个情景

原资料包含一个示例：围绕 2026 年美国中期选举先定义多个可能情景，再分析每个情景可能通过哪些渠道影响美国经济与股票市场。

有用的 prompt 设计原则不是预设某一个选举结果，而是**先定义多个情景，再分别追踪每个情景下的经济和市场传导渠道**。这一示例只是研究结构模式，不代表对任何政治结果的支持或预测。

## 如何使用这套工作流

复杂主题的关键不是写一大段文字，而是在研究开始前明确四件事：

**范围 → 比较维度 → 调查顺序 → 最终输出。**

如果最终研究偏离用户意图，这种结构也更容易定位问题究竟是遗漏了范围、缺少比较维度，还是最终综合格式不对。

## 本使用案例说明了什么

这个工作流展示了如何在 prompt 本身设计研究流程，让复杂多步骤分析始终与最终决策问题相连，而不是变成彼此无关的事实集合。
